## 1. 背景与问题

PromiseLink 的解析流程（互动记录 → InputScope 分类 → 实体抽取 → Todo 生成 → Promise 双向分析 → 关联发现）本质上是一个隐式的窄域 Ontology：4 类核心实体、属性、关系、约束分散在 Pydantic schema、SQLAlchemy 模型与 LLM prompt 三处，无单一事实源、无回归基准。

已发生的一次真实代价：LLM 供应商从 Moka AI 迁移至 DeepSeek 时，解析输出结构只能靠人工比对验证。

详细差异分析见父规划 §1（Ontology 六步对照）。

## 4. 功能需求（FR）

### FR-1 契约生成脚本（W1 核心）

- `scripts/generate_semantic_contract.py`：遍历 Event / Entity / Todo / Promise（复用 todos 表逻辑视图）的 Pydantic schema，生成契约文档骨架
- 输出五节结构：**概念（Class）→ 属性 → 关系 → 约束 → 枚举**（对齐 Ontology 六步，推理规则节留给 W4）
- 生成段落带机器标记（如 `<!-- generated:do-not-edit -->`），人工只在「语义说明」段补充
- 契约版本号 = schema 结构哈希（自动）+ 人工语义版次（手改语义说明时 bump）

### FR-2 契约文档（W1 交付物）

- `docs/spec/PARSING_SEMANTIC_CONTRACT.md` v1.0.0：骨架（生成）+ 语义说明（人工：每字段业务含义、必填性理由、歧义处理策略）
- 关联 REAL 数据流：InputScope 8 类枚举、Promise 双向、纠偏入口字段级标注

### FR-3 CI 契约一致性门禁（W1，双层触发——裁决②落地方案）

| 层 | 触发 | 内容 | LLM 成本 |
|---|---|---|---|
| push 层 | **每次推送 Git**（用户裁决②） | 重跑生成脚本 diff 契约文档；schema↔prompt 版本标注一致性 | 0（纯结构校验） |
| 基准层 | `workflow_dispatch` 手动 + 每周定时 | 全量黄金集 LLM 基准（FR-5） | 有，手动可控 |

> 设计说明：用户裁决②要求 push 也验证。为兼顾「每次推送都验证」与 LLM 成本，push 层跑零成本结构校验（契约漂移当场拦截），全量 LLM 基准保持手动/定时。此折中已在父规划 §4 测试/运维角色意见基础上对齐用户意图。

### FR-4 黄金基准集（W2 核心）

- `tests/golden/` ≥30 条用例，三分层：
  - `must_extract`（≥15）：明确应抽出的人脉/待办/承诺，断言字段级结构（如「答应下周三给方案」→ Promise{双方, deadline=下周三} + Todo）
  - `must_not`（≥5）：闲聊不产生结构（防过度抽取）
  - `ambiguous`（≥10）：多候选人脉/时间歧义，**断言「进入纠偏流程」而非唯一答案**
- 全部合成数据（姓名/公司/电话一律伪造），**真实 PII 不入 git**（红线，见 §6）
- 标注格式：JSON（输入文本 + 期望结构 + 层级标签）

### FR-5 基准跑器（W2）

- `pytest tests/golden/`：参数化执行，LLM 实输出 vs 黄金标注的字段级 diff
- 输出：通过率报告（整体 + 分层 + 分字段），基线值落档后作为回归门槛
- Mock 模式（无 API key）：仅校验用例文件合法性与 schema 可解析性（供 push 层 CI 使用）
- LLM 模式：需显式环境变量 `GOLDEN_RUN_LLM=1`，防止误触发费用

### FR-6 契约版本可观测（W1，轻量）

- pipeline 结构化日志增加 `contract_version` 字段（一行改动）
- 不新增 /metrics 指标（克制，避免仪表盘膨胀）

## 5. 非功能需求（NFR）

| # | 需求 | 指标 |
|---|---|---|
| NFR-1 | 生成脚本执行时间 | < 2s（本地 + CI） |
| NFR-2 | push 层 CI 增加时长 | < 30s |
| NFR-3 | 基准层单次全量 LLM 成本 | 记录并展示，由手动触发控制 |
| NFR-4 | 隐私 | 黄金集/夹具零真实 PII；`must_extract` 用例的人名使用虚构名池 |
| NFR-5 | 兼容 | 不改变运行时行为（除日志加一字段），全量回归 2035+ passed 保持 |

## 6. 安全区与红线（继承父规划 §5）

1. 真实用户数据不入 git（黄金集合成数据、错误样本脱敏后才可入库）
2. 契约文档不含真实用户数据示例
3. LLM 调用必须显式 opt-in（`GOLDEN_RUN_LLM=1`），CI 默认零 LLM 成本
